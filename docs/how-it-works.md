# How it works

The orchestrator makes two decisions before it delegates: how much coordination the task deserves, and which capability should carry each bounded part.

## The routing sequence

1. Understand the requested outcome, audience, format, constraints, and authority boundary.
2. Classify the work as Direct, Team, or Assurance.
3. Keep small and coherent tasks in the root.
4. Delegate only bounded work whose separation improves speed, evidence, or independent verification.
5. Integrate conclusions and artifacts in the root.
6. Apply the highest-value verification for the actual deliverable.
7. Stop before external or irreversible action unless the user authorized it specifically.

## The usage check

Before creating a subagent, the root should be able to complete this sentence:

> This delegation earns its usage because it will improve ________.

Valid answers include parallel speed, specialized artifact work, source independence, or risk detection. “Because the role exists” is not a valid answer.

Each specialist receives only the sources and context required for its bounded assignment. The root should not repeat research or verification after the acceptance criteria pass unless new evidence or a defect creates a reason.

## Direct mode

Use Direct mode when one agent can complete and verify the task without losing important independence. Examples include a short rewrite, a localized document correction, a simple calculation, or a concise factual answer.

## Team mode

Use Team mode when there are one or two genuinely independent workstreams. A market brief might assign source gathering to a researcher while the root studies internal material. A long report might assign evidence extraction and table construction separately.

Do not delegate merely because multiple roles exist. Keep concurrent agents to the minimum useful number.

## Assurance mode

Use Assurance mode for consequential outputs: public materials, financial analysis, executive recommendations, sensitive information, conflicting evidence, or changes that are costly to reverse.

Assurance does not require every role. It normally adds one targeted verifier or an independent Sol reviewer after the artifact exists.

## Model ladder

- **Luna:** focused retrieval, extraction, formatting, checklist verification, and bounded production.
- **Terra:** everyday coordination, synthesis, document analysis, and work requiring sound judgment.
- **Sol:** ambiguous reasoning, high-stakes decisions, and independent review when the consequence justifies it.

Role names remain stable across profiles. Model assignments are profile-specific so the project can adapt without rewriting its operating method.
